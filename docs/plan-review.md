## 1. 已确认目标与边界

替代浏览器日常保存/使用密码的体验，采用独立扩展密码库。密码按条、按版本加密；手机独立确认使用，电脑不会因同步整库或使用一个账号而获得其他密码的解密能力。

用户接受受控办公电脑可以记录当前获批密码及会话；已获得的秘密不能靠超时收回。原生密码库不能通过普通扩展直接改造成密文库，迁移采用可信电脑上用户主动导出的 CSV。

| 事项 | 已确认内容 |
| --- | --- |
| 首验环境 | Windows 11＋Chrome 优先；Android 14，统一 Android 应用 |
| 手机方向 | 考虑 Flutter；无现有硬件安全钥匙 |
| 授权 | 手机扫电脑屏幕；电脑无需摄像头；约 56 字符返回码，可手输或通过用户选定工具传入 |
| 同步 | 数百至上千条；存储由用户指定，默认 Chrome 所关联 Google 账号的 Google Drive |
| 恢复 | 账号仅用于下载密文，另用离线恢复密钥解密；已有完整备份时可以离线恢复 |
| 元数据 | 电脑可以看到站点域名以匹配账号；不因此释放用户名和密码 |
| 手机提醒 | 每次批准后可选择是否及何时提醒修改密码 |
| 后续方向 | Firefox、iOS、具体硬件锁、书签等其他对象 |

## 2. 提交审核的技术选型

| 层 | 推荐选型 | 需要技术验证的部分 |
| --- | --- | --- |
| 扩展 | TypeScript＋WXT＋React，Chrome MV3，明确隔离浏览器 API | 后台休眠、权限、真实表单、Firefox 差异 |
| 手机 | Flutter/Dart；Android Keystore 通过 Kotlin 原生模块调用 | Android 14 真机；Android 12/API 31+ 为候选下限；硬件密钥和认证组合 |
| 凭据加密 | AES-256-GCM；每条记录每次更新独立随机密钥 | nonce/AAD 规则、向量、异常解析 |
| 密钥封装 | RFC 9180 HPKE，P-256/HKDF-SHA-256/AES-256-GCM | 选用支持不可导出 Android 私钥的成熟实现，不能自行拼装替代 HPKE |
| 认证 | 独立 P-256 ECDSA 签名密钥；手机核验记录、设备和版本 | 配对、恢复后身份、回滚检查点与可信显示 |
| 返回方式 | 56 字符单条版本解密码；另推荐会话加密文本供工具传递 | 第二种通常更长，避免渠道获得原始解密密钥；不得暗中降级 |
| 编码 | 规范 CBOR＋有界二维码分帧，手输 Base32＋错误检测 | 实际载荷、扫码稳定性、输入容错和长度上限 |
| 存储 | 默认 Google Drive；首版建议同时提供 HTTPS WebDAV | Drive OAuth/drive.file 多设备授权、WebDAV 能力、同步故障 |
| 恢复 | 独立高熵恢复密钥文件；可选 Argon2id 口令保护 | 旧手机缺失时恢复全流程、材料分离与错误回滚 |
| 组织 | 单仓；扩展 pnpm workspace，Flutter 原生项目独立构建 | 共享协议与向量，不强行共享平台密钥代码 |

P-256 的传统安全强度约 128 位，系统不宣称整体 256 位安全或抗量子。暂按单人多设备产品规划，团队共享、Passkey 提供方和抗量子套件不进入首版。这些是提交审核的范围建议，不伪称用户单独确认过。

## 3. 首版可用范围

必须形成完整闭环：初始化与恢复材料 → 可信配对 → CSV 导入/新建账号 → 密文同步 → 手机逐条批准 → 填充 → 修改提醒 → 新电脑迁移 → 旧手机丢失后的恢复。

Google Drive 默认使用可见应用文件夹及最小的 `drive.file` 权限。首次仍需授权，界面核实实际 Google 账号，不以“已经登录 Chrome”代替 Drive 授权。WebDAV 支持用户指定地址和凭据，不等于支持任意网盘链接。

域名及非敏感别名目录建议独立加密；电脑经配对可获得目录密钥用于匹配，该密钥不能打开凭据。云端只保存目录密文与信封；受控电脑仍能看到目录。手机从记录可信内容核对账号，不信任电脑索引文本。

用户通过工具传入是可选渠道，不接入聊天记录、不自动发送消息、不增加自建中继。手输解密码模式支持离线；使用联网通信工具回传时，该次回传经过其网络。

## 4. 实施顺序与放行条件

| 阶段 | 交付与放行条件 |
| --- | --- |
| P0 当前评审 | 用户审核本计划；产品决策已记录，工程假设与验证项明确 |
| P1 技术验证 | 合成记录跑通 Android 硬件 HPKE、扫码/两种返回格式、Drive OAuth 及可恢复同步故障；验证 WebDAV；失败先调整方案 |
| P2 核心闭环 | Chrome＋Android 保存、核验、逐条授权、填充、手机提醒；无整库凭据解密秘密进入桌面 |
| P3 迁移恢复 | CSV 预览/重复处理、加密备份、独立恢复材料、无旧手机恢复；必须实际演练 |
| P4 多设备 | Drive/WebDAV 全量同步、并发与删除冲突、目录迁移、恢复后重新配对；初步验收 1000 条合成记录 |
| P5 Firefox 与发布 | Firefox 同协议互操作；独立协议/代码审计及修复、最小权限、隐私政策、构建与商店审核资料 |
| P6 后续能力 | iOS、具体硬件锁、书签等逐项评估，不能继承未经验证的安全承诺 |

不会在 P1 完成前把算法库、Android 最低版本和同步细节描述为真机已验证。首版不兼容未经发布的历史草稿格式；需要变更就更新规范与测试向量。

## 5. 评审检查结果

- 已修正原始草稿中的写入封装缺口：电脑使用公钥保存新记录，不需要手机整库对称密钥。
- 已修正手机缺少密文的问题：请求携带目标信封，手机不必为每次授权联网或预存整库。
- 已分开手输静态版本解密码与会话加密响应；前者无到期保证，后者也不能收回恶意电脑已取得的秘密。
- 已明确浏览器同步容量限制、Drive 首次授权、跨账号边界、非事务同步、恢复和独立备份。
- 已消除“手机独占索引密钥却要求电脑本地匹配”的矛盾，限定目录密钥的用途。
- 已修正对受控电脑、手机失陷、恢复材料泄露、记录来源与回滚的保证范围。
- 当前是文档自审与官方能力核对；未做密码协议独立审计、原型、真机测试或商店审核。
