## 1. 传输与编码

请求采用规范 CBOR 与有界二维码分帧。每帧包含消息 ID、序号、总帧数和错误检测；接收端限制总字节数、帧数、组帧时间及内存。不信任压缩比，首版不依赖压缩密文提高容量。

电脑无需摄像头。返回为约 56 字符的版本解密码或供用户转送/粘贴的完整会话加密响应；插件和手机不自动发送第三方消息。

消息类型、库、版本、套件和用途必须进入相应签名/AEAD 上下文；不同类型不能复用未区分的签名字符串。精确字节编码与测试向量在 P1 固定。

## 2. 初始化与配对

1. 可信手机创建长期签名/解密密钥、独立恢复材料及公开库描述符；用户保存恢复材料并验证备份流程。
2. 扩展经所选存储或一次性文件取得公开描述符，用户在两端核对由完整公钥材料派生的指纹，固定手机/恢复公钥。
3. 扩展生成每设备签名身份、单次配对加密密钥对和配对挑战，显示包含两种公钥及库 ID 的二维码。手机扫描、确认设备与权限并登记；签名密钥与加密密钥分离。
4. 手机通过所选存储或用户传递的加密文件/文本发布配对确认；把仅用于匹配的目录密钥封装给该电脑的单次配对加密公钥，并签署完整配对摘要。无电脑摄像头时不能隐含要求反向扫码。
5. 两端核对配对摘要后保存状态。密钥更换、新设备及恢复后的配对重新确认，浏览器账号同步不自动授权。

第一次设置可以使用网络存储，与后续逐条授权可离线分开描述。若首次也完全离线，需要一次性文件或手工公钥传递；未交换公钥就无法建立密码学配对。

## 3. 扫码请求

电脑请求必须提供具体记录版本的密文信封、设备认证、已核验凭证（若有）、256 位随机挑战和请求摘要所需上下文。会话响应模式提供临时公钥；不能请求多个记录或让手机执行任意操作。

手机按以下顺序处理：有界解析 → 识别配对/权限 → 核对信封和已见版本 → 按本地认证政策打开当前记录 → 从可信内容显示站点/账号和请求设备 → 明确逐条批准或拒绝。

新版本需单独核验，旧版本/并发冲突需提示。手机持有本地检查点即可离线完成已见记录检查；没有检查点时不能假称已证明全局最新。

电脑提供的 URL、时间和设备名称不作为可信事实。手机使用本地接收时间控制待审批窗口，限制异常请求频率；请求中的 expiresAt 只可作为额外约束，不能用来证明电脑诚实。

## 4. 两种返回语义

| 返回类型 | 内容与验证 | 明确限制 |
| --- | --- | --- |
| ManualCode | 当前 K_record；Base32 与输错校验；电脑对当前记录执行 AEAD 验证 | 没有响应签名/挑战有效期，可重复解密当前版本 |
| EncryptedResponse | 本次必要凭据字段经 HPKE 加密给临时公钥；手机签名绑定请求摘要与密文 | 正常扩展可拒绝错会话/过期/重复，但恶意电脑可保留会话私钥和明文 |

返回格式纳入扫码请求，不能因验证失败而自动换为低保护格式。手机批准单条后可选择提醒；只有用户明确动作才复制或分享文本。

## 5. 手机与扩展状态

手机：未配对 → 已配对；单次请求：待验证 → 待核验/待用户批准 → 已拒绝或已批准 → 返回已生成。异常格式、权限错误、重复挑战与记录替换不进入返回已生成状态。

正常扩展：已缓存密文 → 请求生成 → 等待返回 → 已验证 → 短暂使用 → 清理会话。浏览器重启或后台丢失会话时，不从同步数据恢复临时私钥；手输模式由用户重新选择记录，不能自动使用历史解密码。

审批后的提醒表示“已批准释放”，不证明网站成功登录或密码实际修改。用户可以手动延期/标记完成。

## 6. 协议测试门槛

跨端固定向量覆盖成功、签名/AEAD 失败、未知套件、收件方替换、跨库/记录/版本替换、二维码混帧超限、同挑战重放、两种格式混淆、目录授权冒充凭据授权、手机吊销与恢复后重新配对。

标准 HPKE 只解决公钥加密的一部分目标；身份、可信显示、回滚、限次及状态机必须分别评审。明确不提供“恶意电脑已经得到的密码自动失效”保证。
