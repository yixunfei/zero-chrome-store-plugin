## 1. 总体目标

让用户在个人和受管理的办公电脑之间使用必要账号，避免仅因同步浏览器数据或批准一次使用而使其他密码获得可解密性。将解密与授权能力放在独立手机，浏览器持久化密文，手机对每次释放作出明确确认。

用户原始要求：替代浏览器密码管理、逐条手机验证、使用后修改提醒、现有密码迁移、多设备密文同步、强加密、尽量无额外通信、可扩展其他浏览器数据。本次先确认方案与需求文档，再进入开发。

已确认：独立库、接受单条使用暴露、Android 14、Windows 11＋Chrome 优先、无硬件锁、数百至上千账号、电脑可见域名、无电脑摄像头、手机扫码＋约 56 字符返回码，允许自行通过工具传入。考虑 Flutter，Android 使用同一套应用。存储由用户指定，默认 Chrome 所关联 Google 账号的 Google Drive；账号只负责下载密文，恢复使用独立离线密钥。

## 2. 推荐首版范围

先在 Windows 11＋Chrome 和 Android 14 完成端到端闭环，再完成 Firefox。推荐 Flutter 共享界面与业务、Kotlin 原生安全模块，后续 iOS 增加 Swift 安全模块；同一套 Android 应用候选支持 Android 12/API 31 及以上，具体下限与硬件要求通过原型验证，不为手机型号建立独立业务分支。具体技术栈仍需评审。

首版建议包含：单条保存/更新、逐条确认填充、手机本地提醒、Chrome/Firefox CSV 导入、配对与设备权限、Google Drive 默认全量密文同步、HTTPS WebDAV 自定义存储、浏览器小型配置同步、离线加密备份及恢复演练。WebDAV 为本轮明确提出的范围建议，不代表用户指定支持所有网盘。

首版建议暂不包含：通用 Passkey 提供方、手机系统自动填充服务、TOTP 种子管理、团队共享与企业权限系统、硬件锁通用适配、书签/历史/标签页加密、附件、自建服务器。原始诉求中的“公共服务账号”暂按个人管理的账号理解；多人共享须另行确认。

## 3. 功能需求

| 编号 | 要求 | 验收重点 |
| --- | --- | --- |
| F-01 | 建立密码库与可信手机配对，验证公钥指纹或由完整配对摘要派生的短语 | 中间人替换、公钥更换和重复配对不能静默通过 |
| F-02 | 为每台电脑登记独立身份与权限，手机可标记办公设备 | 浏览器账号相同不等于自动获得手机授权；未配对设备不能请求释放 |
| F-03 | 保存/更新新账号后，扩展仅持久化密文 | 保存不需要整库解密密钥；普通页面、后台日志与同步对象不持久化明文 |
| F-04 | 记录每次更新生成新密钥和新版本；手机核验记录来源及版本 | 未核验新记录与已核验记录明确区分，不能静默替换已核验站点 |
| F-05 | 手机每次明确确认一条凭据记录的指定版本 | 返回码只能解开该版本的凭据 payload；释放 A 不提供解开 B 的能力，拒绝批量请求；不声称能限制恶意电脑只能填充不能显示 |
| F-06 | 按用户触发执行填充，匹配可信浏览器提供的页面来源 | 正常客户端校验 HTTPS、精确来源及跳转/iframe；恶意浏览器无法被这些检查证明安全 |
| F-07 | 手机针对设备限制可释放的账号，高价值账号可禁止释放 | 限制在手机执行；修改桌面 UI 或伪造“家庭电脑模式”不能解除策略 |
| F-08 | 手机批准后可选择不提醒、预设时长或自定义时间 | 提醒不包含密码；默认锁屏通知不展示站点和用户名；支持延期和手动标记已修改 |
| F-09 | 导入 Chrome/Firefox CSV，提供预览、重复处理和错误报告 | 覆盖编码、引号、多行、空字段、重复站点/账号、大文件边界；部分失败不能默默丢失记录 |
| F-10 | 导入在可信电脑进行；迁移完成后指导原生副本清理 | 导入不自动删除原文件或原生密码，先完成条数核对、抽样使用和恢复验证 |
| F-11 | 在权限允许时关闭原生保存提示，报告设置控制状态 | 企业策略阻止时明确显示；不声称清理了已有密码或阻止了管理员监控 |
| F-12 | 用户指定存储，默认 Google Drive；浏览器账号同步小型配置 | 覆盖数百至上千条；首次明确 OAuth 授权并展示实际账号；拒绝、配额不足、离线和账号切换不造成静默丢失/错库合并 |
| F-13 | 多设备同时更新、删除、离线重连时保留可恢复结果 | 非事务写入中断、同条并发修改和删除冲突不得静默覆盖 |
| F-14 | 加密包支持跨 Chrome/Firefox 迁移与独立备份 | 包中无明文密码或手机硬件私钥；新设备仍需手机配对 |
| F-15 | 二维码传输有大小、分帧数、时限与解析资源上限 | 混帧、重复、乱序、截断、超限、未知版本和篡改不能触发错误授权或耗尽资源 |
| F-16 | 手机可删除/吊销桌面配对关系 | 该手机之后拒绝相应设备；明确无法撤回已泄露密码，也无法通知完全离线的其他手机 |
| F-17 | 离线恢复流程创建新手机密钥并重新封装记录；账号只下载密文 | 演练“旧手机不可用＋新手机＋密文备份＋独立恢复材料”；已有完整备份无需账号即可恢复，不引入在线强制验证 |
| F-18 | 支持手输或用户主动粘贴约 56 字符凭据；二维码载荷可分帧 | 分组、易混字符和错误校验一致；只在扩展自身页面接收，不在网页收取解密码，不自动监听剪贴板 |
| F-19（建议） | 用户选择工具回传时，手机提供加密给本次浏览器会话的完整响应 | 通信工具仅取得密文；验证请求摘要、手机签名与会话绑定；拒绝错会话/篡改/正常客户端重放，不限制为 56 字符 |
| F-20（建议） | 首版可配置 HTTPS WebDAV，保留本地加密备份导入/导出 | 用户指定地址/路径/凭据；权限与令牌按设备隔离；存储切换先验证完整性，不删除原库、不向跨源跳转泄露凭据 |
| F-21（建议） | 匹配目录独立加密，配对时授予电脑目录访问能力 | 仅域名/非敏感别名可查，目录密钥不能解开凭据；新电脑取得能力，手机不信任目录作为记录来源证明 |

F-06 首版默认精确来源匹配；跨子域、跨域 SSO、HTTP、跨源 iframe 与复杂表单分别定义策略，不以任意字符串包含或仅比较可注册域代替安全来源校验。无法识别的表单应停止自动填充并提供受控的人工路径。

F-08 的触发事件是“手机批准释放”。无服务器且电脑不可信时，不能可靠证明密码已实际使用或已修改；提醒和完成状态以用户确认与手机记录为准。

## 4. 安全要求

| 编号 | 必须满足 |
| --- | --- |
| S-01 | 电脑、同步对象及普通导出包不包含整库私钥、恢复私钥、手机硬件私钥或可批量解密凭据的共享秘密；允许经手机授权给电脑的目录密钥仅用于域名/非敏感别名 |
| S-02 | 手机是信任根；电脑允许按完全受控建模，保证限于未批准记录的机密性，不能依赖电脑遵守清理或审批策略 |
| S-03 | 逐条独立随机数据密钥、标准 AEAD、公钥信封、协议域隔离与完整上下文绑定；禁止自创密码算法 |
| S-04 | 扫码请求绑定库、设备、记录、版本、密文摘要与审批上下文；56 字符码是当前版本数据密钥，不能宣称自动过期。会话加密格式另绑定挑战和临时公钥，由手机签署请求摘要；两种格式不得静默降级 |
| S-05 | 手机对释放操作执行用户确认，设备解锁不能被扩展解释为整库授权；会话缓存不得扩大至批量释放 |
| S-06 | 6 位动态码不能作为独立解密密钥或仅由桌面验证的保护；盐不增加短码自身的秘密熵 |
| S-07 | 记录真实性与版本新鲜度分开处理；签名防篡改不等于防回滚；手机保存必要检查点并披露离线限制 |
| S-08 | 请求限次、失败退避、异常连续账号请求提示在手机执行；审批界面不得由请求任意指定可信显示文本 |
| S-09 | 无用户动作不读写剪贴板；允许明确触发复制/粘贴，分享优先会话密文。无默认遥测和明文调试日志；不自动发消息、不接入聊天记录；代码随安装包提供，最小权限和固定依赖版本 |
| S-10 | 原生硬件能力需真机检查，软件回退不能静默发生或继续标记为硬件保护 |
| S-11 | 手机私钥不可导出；恢复采用另一个明确的授权路径，恢复材料的能力和泄露后果必须向用户说明 |
| S-12 | 任何高风险账号都可设置不向办公设备释放；手机失陷、恢复密钥泄露与审批后的明文泄露属于明确边界 |

对称算法 256 位、ECC 传统安全强度约 128 位是本次推荐套件；首版范围建议不包含抗量子，随整体方案审核。不能把“多层加密”“加盐”或“硬件钥匙”当作未定义的最高安全指标。

## 5. 恢复与多手机

推荐恢复路径：创建独立高熵恢复密钥及公钥；记录密钥同时封装给手机和恢复公钥。浏览器仅存恢复公钥及信封，恢复私密材料离线保管。

已确认账号仅用于取得云端密文，不作为密码学第二因素。已有密文副本与独立恢复材料时，可以完全离线恢复；不使用账号 ID/账号密码派生密钥，不另建强制验证服务。默认存储、OAuth、目录授权和完整恢复步骤见 [存储与恢复](storage-and-recovery.md)。

恢复必须同时具备密文备份与恢复材料。恢复材料不是完整库备份；只有同步云端也不保证数据仍然存在。恢复时在可信新手机或专门可信环境创建新硬件密钥，解开恢复信封并重新封装，不尝试导出或复制旧手机硬件私钥。

遗失手机后，新配对、撤销旧授权和重封装不能让旧备份及已释放密码失效。若怀疑旧手机或恢复材料已泄露，应在可信环境更换网站密码。

多手机会增加每条记录的信封体积、授权策略同步与吊销复杂度。建议先支持主手机＋离线恢复；是否首版双手机待确认。加密库的主手机整体失陷仍可能影响全部记录，逐条密钥主要限制向电脑释放的范围。

## 6. 工程与模块边界

- 扩展模块：记录库、同步适配器、配对/授权状态机、导入导出、网页表单适配、管理界面。
- 手机模块：硬件密钥适配、可信记录目录、审批策略、二维码传输、提醒、恢复与设备管理。
- 共享资料：协议字段规范、算法套件标识、状态机、跨端测试向量、恶意输入样本。Flutter 共享界面与适当业务，平台安全接口分别实现；local_auth 的成功布尔值不能替代密钥使用认证。
- 传输、存储和密码操作通过明确接口隔离，后续扩展书签等对象类型不应修改授权核心。
- 遵守工作区代码规范：单文件一般不超过 1500 行，特殊复杂文件不超过 2500 行，单函数不超过 100 行；按职责划分而非机械拆分。超过限制须提示。
- 当前按未发布新项目处理，不预先承担旧格式兼容包袱；协议字段版本用于拒绝错误解释，是否支持迁移另行决定。
- 实际 Web 页面设计开始前读取用户提供的设计规范。当前扩展仅为 P1 探针，没有密码填充界面。
- 当前仅开发合成数据技术探针；正式发布门槛见 [P1 报告](p1-report.md)。

## 8. 验收场景

1. 从公司电脑复制整个扩展目录及同步对象，在没有手机和恢复材料时不能解密记录。
2. 电脑请求 A，手机批准后，不能用该结果解密 B 或 A 的未来更新版本；该密钥下只存本次允许释放的凭据字段，其他敏感类型独立加密。
3. 攻击者修改记录 ID、版本、域名、收件方公钥、密文或二维码分帧，手机/正常扩展拒绝不一致消息；检查长码编码规范与输错处理。
4. 电脑伪造手机确认状态、取消超时或绕过 UI，仍不能让手机释放未批准记录。
5. 手机审批界面显示与可信记录一致的站点/账号；未核验记录及回滚风险不可伪装成已核验。
6. 确认恶意主机可以捕获获批密码，并验证文档和产品没有声称能阻止此事；确认手机账户白名单能限制后续请求。
7. 用合成的 50/100/500/1000 条样本测量真实序列化体积、外部存储同步开销、二维码载荷与解析时间，不用名义密码长度估算容量。
8. 同步中断、断网、写入超额、双设备冲突和删除竞争后可恢复，无静默数据覆盖。
9. 新手机通过离线材料恢复，重新配对新电脑；缺少备份或恢复材料时明确说明不可恢复条件。
10. 手机通知被拒绝、系统延迟、无相机、扩展被策略限制时提供真实状态，不承诺后台总能工作。
11. 复制/粘贴由用户主动触发；通信工具取得会话响应和记录密文时，缺少浏览器会话私钥不能解开响应。原始 56 字符码不具备此渠道保密性，产品不得混淆两种格式。
12. Android 14 作为首验环境，拟支持的最低及其他系统版本使用同一套应用验证；硬件不足明确报告，不静默降低密钥保护等级。
13. 首次 Drive 授权、被拒绝、授权实际账号与 Chrome 账号不一致、过期令牌和 WebDAV 重定向分别测试；登录浏览器不能绕过存储授权或解密。
14. 复制密文后可用离线恢复材料恢复，无需再次账号验证；缺少恢复材料不能仅通过 Google 登录解密。

## 9. 确认方式

用户产品决策及工程验证项见 [决策登记](decision-register.md)。架构、协议和数据文档已按当前方向统一修订，现在提交 [整体方案](plan-review.md) 审核；工程建议不自动等于用户批准。审核后按 P1 技术验证开始，不直接发布或操作真实密码。
