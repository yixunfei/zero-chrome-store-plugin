## 1. 用户已确认

| ID | 决策 | 内容 |
| --- | --- | --- |
| D01 | 安全目标 | 接受当前使用的密码可能被受控电脑捕获，重点保护其他未批准记录和整个库 |
| D02 | 密码库 | 独立扩展密码库，保留浏览器账号同步能力，不直接改造原生密码数据库 |
| D03 | 交互 | 手机扫电脑屏幕；电脑无摄像头；约 56 字符返回码可手输或用户通过第三方工具传入；二维码载荷可以更长 |
| D04 | 验证形式 | 已从普通 6 位动态码调整为离线扫码与长返回凭据；不再以 6 位码保护长期密文 |
| D05 | 平台 | Windows 11＋Chrome 优先；Android 14 首验，同一 Android 应用覆盖受支持版本；考虑 Flutter |
| D06 | 环境 | 按允许安装扩展、禁止电脑摄像头理解并经补充核对；不绕过企业策略 |
| D07 | 数据规模 | 数百至上千账号全部自动同步，允许用户指定密文存储 |
| D08 | 默认存储 | 默认 Chrome 所关联 Google 账号的 Google Drive；由用户选择具体存储 |
| D09 | 元数据 | 电脑可看到站点域名以进行匹配；不因此解开用户名/密码 |
| D10 | 恢复 | 账号仅下载密文，另用独立离线恢复密钥解密；复制备份后不强制再次账号验证 |
| D11 | 硬件现状 | 当前无硬件安全钥匙，先以 Android 手机完成核心功能 |
| D12 | 工作阶段 | 先评估、核对、选型、需求与计划审核，再进入开发 |

## 2. 提交整体审核的工程选择

| ID | 推荐 | 理由/验证门槛 |
| --- | --- | --- |
| T01 | TypeScript＋WXT＋React 扩展，Flutter＋Kotlin 安全模块 | 模块隔离，Android 长期私钥不可导出；真实平台验证 |
| T02 | Android 12/API 31+ 候选下限，14 首验 | 同一应用检测硬件能力；不承诺全部旧系统或全部硬件等级一致 |
| T03 | 每条每版本随机 AES-256-GCM 密钥，HPKE P-256 信封，独立 ECDSA 签名 | 公钥保存、逐条释放；成熟库与不可导出私钥接口在 P1 验证 |
| T04 | 56 字符解密码＋会话加密文本两种格式 | 手输可离线，工具传输优先密文；不混淆到期/重放保证 |
| T05 | Google Drive drive.file 可见文件夹；首版增加 HTTPS WebDAV | 默认最小权限、可下载迁移，给“用户指定”提供实际支持；OAuth 与能力验证 |
| T06 | 目录独立加密，手机配对授予电脑目录密钥 | 电脑本地匹配且云端不直接看到域名，目录能力不能解密凭据 |
| T07 | 不可变记录版本＋完整提交＋显式冲突 | 非事务存储下处理部分上传/删除/并发，需故障验证 |
| T08 | 高熵恢复材料与密文备份分开；可选 Argon2id 保护文件 | 实际演练旧手机缺失恢复；账号不作为密钥或强制在线因素 |

## 3. 首版范围建议与后续事项

按单人多设备使用规划，先主手机＋离线恢复，不实施多人共享、通用 Passkey 提供方、TOTP 种子库、附件、抗量子套件或任意型号硬件锁。Chrome/Android 先形成闭环，Firefox 随后完成并进入浏览器发布门槛，iOS 后续。

这些范围随整体计划确认，不作为新增逐条问卷。若用户明确需要团队共享或抗量子等，再调整架构。

Cloud/OAuth 项目、稳定扩展 ID、商店主体及独立审计资源在对应阶段需要落实；不阻止现在完成规划，也不提前向用户索取凭据或进行外部账户操作。
