## 1. 信任与资产

可信根是未失陷的手机、安全密钥使用实现、用户在手机上的核对，以及妥善离线保存的恢复材料。办公电脑可以完全受控；个人初始化/恢复环境需可信。云存储与第三方传输渠道不被信任为凭据保密方。

资产包括逐条用户名/密码、手机与恢复私钥、配对及权限、可信版本检查点、密文库及可恢复性。域名/非敏感别名可对配对电脑暴露，云端目录建议单独加密；请求大小、数量和时序仍可能泄露。

## 2. 场景与保证范围

| 场景 | 设计目标 | 限制 |
| --- | --- | --- |
| 同步云盘/备份被复制 | 无手机或恢复私钥无法批量解密凭据 | 元数据规模仍可见；秘密失陷后的旧密文不具备前向保密 |
| 整台办公电脑失陷 | 其他未批准凭据仍保持加密 | 当前使用密码、存入的新密码、目录与登录会话可被捕获 |
| 原始 56 字符码泄露 | 不扩散到其他条目/未来版本 | 取得对应密文后可重复解开当前版本 |
| 会话加密文本被聊天渠道保存 | 渠道缺少浏览器会话私钥时不能打开响应 | 恶意获批电脑可永久保留解密材料 |
| 恶意页面诱导填充 | 正常扩展检查来源、页面变化和用户动作 | 完全受控浏览器无法被此证明安全 |
| 云端替换/回滚对象 | 签名、哈希、AEAD 和手机检查点检测已知不一致 | 未见历史和服务器隐瞒更新无法完全检测 |
| 云端删除或账号不可达 | 本地密文缓存、独立备份可恢复 | 加密不保证可用性；Google Drive 历史非唯一备份 |
| 手机丢失 | 硬件授权提高私钥使用门槛；独立材料可恢复 | 不承诺失陷手机安全，旧设备无法被离线远程抹除 |
| 手机或恢复私钥完全失陷 | 记录为重大事件，重新配对并更换网站密码 | 可能影响整库；逐条密钥不消除其全库授权能力 |

## 3. 必须避免的错误保证

- “只批准一次”不等于网站密码只能使用一次。超时和清理不能收回已经释放的密码。
- 配对签名证明设备密钥持有，不证明主机清洁、不可监控或确实位于某网站。
- 用户连续批准多个账号会扩大攻击者可收集的范围。手机端白名单、拒绝释放和异常请求提示降低风险，但不替代用户核对。
- 登录 Google 账号只获得密文下载权限；已复制的密文不受之后账号退出、撤销或重新认证的解密限制。
- 新记录可由公开收件方密钥加密，必须区分未核验对象；不能把成功解密当作来源证明。
- Passkey 可以减少可复用密码暴露，但不能保护受控主机中的会话。本项目首版不实现通用 Passkey 提供方。

## 4. 验证重点

测试跨记录/版本替换、未配对设备、手机策略绕过、旧检查点、两种返回格式混淆、解析超限、同步中断及恢复材料错误。对受控电脑能力用负面验证明确“不提供的保证”，而非仅测试正常客户端界面。

发布前需独立协议与代码审计、构建/依赖审查和真实浏览器/手机测试。本轮仅文档评审，未据此宣称可投入真实密码使用。
