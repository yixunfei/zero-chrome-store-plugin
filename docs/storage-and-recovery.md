## 1. 产品行为

- 初次设置推荐 Google Drive，明确展示实际授权的账号和密码库位置。用户可以选择其他受支持存储，切换前先完成备份和目标库验证。
- 浏览器账号同步仅携带小型配置、库标识及非敏感存储定位信息；完整库不使用约 100 KiB 的 `storage.sync`。
- 首版建议提供 Google Drive 与 HTTPS WebDAV 两个适配器。用户填写 WebDAV 地址、路径和认证信息；不声称可输入任意网盘 URL 即自动兼容。OneDrive 等通过后续专用适配器接入。
- 本地加密文件导入/导出始终可用，是独立备份和手动迁移渠道，不冒充自动同步服务。
- 密文同步需要网络。记录已缓存且完成手机配对后，扫码、56 字符码解密和本地提醒可以离线完成。

## 2. Google Drive 默认实现

### 账号与 OAuth

Chrome 使用公开 `chrome.identity` 能力申请 Drive OAuth 授权。API 默认会优先使用同步账号，否则可能使用配置文件中的其他 Google 账号，因此产品必须显示实际授权身份，不能只显示“当前 Chrome 账号”并假定两者相同。

首次访问 Drive 需要用户授权；浏览器登录状态、`getProfileUserInfo` 返回的信息不等于 Drive 权限或重新认证。无可用账号、拒绝授权、企业阻止访问、网络不可达或令牌失效时明确显示状态，并保留本地密文。不得私自切换账号或上传到另一账号。

扩展是公开客户端，不在包中嵌入 OAuth client secret。需要创建 Google Cloud 项目、启用 Drive API、配置 OAuth 同意信息和与扩展 ID 对应的客户端。Android/未来 Firefox 使用各自合适的公开客户端流程，不复用或同步 Chrome 的访问令牌。跨客户端访问同一应用文件的行为必须在 P1/P4 用实际项目验证。

### 权限与位置

推荐 `https://www.googleapis.com/auth/drive.file`，只处理本应用创建或用户明确授权的文件，首建可见的 `Zero Browser Vault` 文件夹。保存真实 folderId/fileId，不根据可重复的文件名判定唯一身份。

用户选已有目录或库时采用受支持的选择/授权流程；选择一个目录不应被解释为自动获得其中所有既有文件的访问权。目录发现、已有库导入和多设备访问的授权边界必须真实验证，不请求整个 Drive 的读写权限来掩盖问题。

没有选择 `appDataFolder` 作为唯一默认密码库：它具有最小权限优势，但内容不在 Drive 普通界面展示，不能分享或移出该空间，用户移除应用数据时可删除。用户要求自行下载、备份和迁移密文，可见文件更合适。即使未来使用 appDataFolder 存配置，也不能把它作为唯一可恢复副本。

### 自动同步的含义

Chrome 扩展运行或被允许的事件唤醒时，执行初始拉取、变更后上传、启动/联网后的追赶和定期检查。MV3 后台可能休眠，浏览器关闭时不能保证实时同步；状态应区分“仅本地”“待上传”“远端已确认”“冲突”“需重新授权”。

Drive 可用 changes API 增量拉取；游标只在结果处理成功后提交。处理分页、删除、授权变化、重复响应及断网重试，必要时全量重新枚举；没有后台 Webhook 接收服务器，因此不承诺实时推送。

限流采用有界指数退避与抖动，身份失效和配额不足不能无限重试。令牌由浏览器身份设施管理或仅按当前设备必要方式保存，禁止进入 `storage.sync`、导出包和日志。

## 3. 统一存储接口与同步数据

存储适配器只承担对象枚举、读取、上传、删除及能力声明；授权接口与密码操作分离。存储不能收到记录数据密钥、手机私钥或恢复私钥。

推荐按不可变版本对象和提交记录同步：

1. 先在本地完成一批记录信封、目录密文和引用摘要。
2. 上传所需对象并确认成功，再上传包含对象引用、内容哈希和父版本的提交记录。
3. 接收端仅接受引用齐全、哈希一致、签名及格式有效的提交；缺少对象时保持待完成状态，不把半个库覆盖本地。
4. 多个设备的更新以父版本关系识别并发。相同记录并发修改、删除与更新冲突保留双方，用户解决；不使用本地时间最后写入覆盖。
5. 删除先形成 tombstone，不立即清除所有历史。首版保守保留恢复窗口，物理清理策略在故障原型后确定。

这不是已经证明正确的同步协议。P1 需验证 Google Drive/WebDAV 的列举、对象可见性、幂等重试、条件写入等真实行为；上层不能假定多个文件写入是事务，也不能只依赖 ETag 就宣称实现完整冲突处理。

存储可以隐藏、重放或删除数据，签名不保证完整性意义上的“所有数据仍在”。手机对已见记录保存检查点，只能检测其已知范围的回滚。独立密文备份是可用性保障，云盘历史不是唯一备份。

### 元数据

桌面允许看到域名和用户自行指定的非敏感别名，用户名和密码保持逐条加密。建议同步目录单独加密，使用仅能打开目录的 `K_directory`；经手机配对授权后桌面可以持有它，云端仅保存其信封。它不是解开凭据的主密钥。

新电脑在配对时通过手机获得目录访问能力，随后可本地匹配站点。手机/恢复收件方也封装该目录密钥，以便迁移和恢复；不得在普通浏览器同步中放目录明文或密钥。目录信息被受控电脑读取是已接受边界，不能宣称该设计对管理员隐藏站点。目录不能作为手机可信显示来源；手机必须从对应记录的可信内容验证站点和账号。

对象文件名使用随机标识，不包含域名、账号或密码。对象大小、数量、访问时间仍可能被存储方观察。

## 4. 自定义存储与切换

首版建议以 HTTPS WebDAV 代表可配置存储：仅允许用户授权的目标来源；跨源跳转不携带认证信息，不关闭 TLS 证书验证。浏览器 host 权限按用户配置申请，不能默认把访问凭据发送到任意域名。

WebDAV 部署的认证、方法、锁和 ETag 语义不一致，需要公布首批验证过的能力范围。若环境缺少必要能力，应报告不能自动同步，保留加密文件备份；不默默按“最后写入覆盖”降级。

切换存储不更换密码库身份和手机密钥：先上传、读取验证并检查对象覆盖，再切换本地配置；保留原库直到用户自行决定清理。账户或库不匹配时必须停止合并。切换账号不会给新账号自动提供解密能力。

## 5. 恢复材料

用户已选择的语义是：**账号控制云端密文下载，离线恢复密钥控制解密。** 密文被复制后，恢复不再需要账号；不引入强制在线验证、秘密分片服务或账号密码派生解密密钥。

推荐初始化时在可信手机生成独立恢复密钥对，公钥加入密码库收件方；离线私密材料导出到用户保管的恢复文件。可用独立高熵备份口令加密该文件，口令保护使用 Argon2id；具体参数需目标设备基准测试。默认推荐高熵密钥文件，不使用 Google 密码、短 PIN 或 6 位码作恢复根。

恢复私密材料不上传到同一同步库，也不长期保存在办公电脑。公开恢复公钥及记录密钥信封可以同步。每条凭据和目录的密钥均有对应恢复信封，备份清单包含恢复所需算法、身份和完整性资料。

不能混淆两个文件：密文库备份包含加密数据；离线恢复材料包含解密权。缺少前者无法凭空恢复数据，缺少后者且没有可用手机则无法解密。

## 6. 恢复演练

1. 在可信环境，从 Google Drive/WebDAV 下载密文，或直接使用已保存的离线密文备份。
2. 用户导入独立恢复材料，检查库标识、恢复公钥指纹和完整性；错误材料应明确失败，不覆写原备份。
3. 新手机创建新的不可导出硬件密钥。恢复操作逐条打开恢复信封，封装给新手机；只保留执行需要的秘密，禁止日志泄漏。
4. 重建记录核验状态和目录，登记新的设备策略，重新配对电脑；恢复不能凭空证明备份比丢失手机曾见过的版本更新。
5. 验证条数、抽样解密和新增更新操作，再提交新配置；恢复材料轮换按单独明确步骤进行，避免只更新部分记录。

恢复后旧手机及旧备份不能被远程收回。若怀疑私钥、恢复材料或网站密码泄露，需要更换受影响的网站密码；仅重新封装旧数据不能消除旧副本的解密能力。
